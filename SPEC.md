# Register Check: SPEC (v0, devnet)

Source of truth for v0. Derived from prd.md (locked) and poc_plan.md. Toolchain facts are in CLAUDE.md.
If code and this spec disagree, fix one of them in the same commit.

## 0. Decisions that shape everything

| # | Decision | Why |
|---|---|---|
| D1 | **rc-ingest uses raw JSON-RPC** (`reqwest` + `serde_json`, `encoding: jsonParsed`, `commitment: finalized`), not `solana-rpc-client`. Addresses are base58 `String`s. | Keeps the core free of Solana crates. Avoids two `solana-pubkey` majors and the 4.5-alpha MSRV trap. jsonParsed already decodes Token-2022 instructions. Faster builds on a tight disk. |
| D2 | Solana crates (`~4.1`) appear only in `rc-cli` under the default feature `attest`, to send `post_result`. | Isolates the heavy dependency tree to one place. |
| D3 | Amounts are raw base units, Arrow `UInt64`. Rules **cast to `DECIMAL(38,0)` before any multiplication**. | `u64::MAX * 10000` overflows u64. Decimal128(38) holds u64 × 10^19. |
| D4 | `supply_after` is computed by rc-ingest as a running sum over the **full mint history** (mint creation onward), ordered by `(slot, tx_index)`. After every poll, the result is reconciled against `getTokenSupply(finalized)`. | Token supply isn't in tx meta. Reconciliation catches unparsed mint variants (red-team a): a mismatch becomes a `SupplyDrift` error and a pseudo-violation `R0_supply_drift`. |
| D5 | Rules are static `.sql` files with **no parameters or string interpolation**. The R3 threshold (20%) is a literal in the SQL. | Removes SQL injection via config (red-team l) by construction. |
| D6 | Reserve attestations must carry a valid **ed25519 signature** from an attestor key listed in config. Bad, unknown-key, or future-dated ones are rejected before reaching the `reserves` table. | Spoof/replay defence (red-team j). |
| D7 | Proof JSON is canonical: a `serde_json::Value` (BTreeMap means sorted keys), compact, amounts as **strings**. `result_hash = sha256(canonical JSON without result_hash and attested_tx)`. | Deterministic. Strings keep JS dashboards exact above 2^53. |
| D8 | On-chain `Result` PDA is seeded by `result_hash`. | Two checks in one slot can't collide; re-posting the same result fails (idempotent). |

## 2. Arrow table schemas (rc-types::schema)

All `mint`/owner/authority/signature columns are `Utf8` (base58). Amounts are `UInt64` base units. `slot` is `UInt64`. None nullable unless marked.

| Table | Columns |
|---|---|
| mints | mint Utf8, slot UInt64, tx_index UInt32, ix_index UInt32, signature Utf8, amount UInt64, supply_after UInt64, authority Utf8 |
| burns | mint, slot, tx_index, ix_index, signature, amount UInt64, supply_after UInt64, authority Utf8, via_permanent_delegate Boolean |
| transfers | mint, slot, tx_index, ix_index, signature, from_owner Utf8, to_owner Utf8, amount UInt64 |
| balances | mint Utf8, owner Utf8, amount UInt64, slot UInt64 (snapshot at that slot, one row per mint+owner) |
| authority_changes | mint, slot, tx_index, ix_index, signature, change_kind Utf8, old_value Utf8 (nullable), new_value Utf8 (nullable) |
| reserves | mint Utf8, as_of_ts Timestamp(Second, UTC), reserve_amount UInt64, attestor Utf8, sig Utf8, source_url Utf8 |
| allowlist | mint Utf8, owner Utf8 |

`tx_index` (position in the block) and `ix_index` (instruction position within the tx, inner and batch-wrapped instructions numbered in execution order) are additions to the PRD data model. Events order by `(slot, tx_index, ix_index)`; this keeps same-slot and same-tx ordering deterministic (red-team c, m).

`change_kind` ∈ {`mint_authority`, `freeze_authority`, `permanent_delegate`, `transfer_hook_program`, `close_authority`, `other`}.

Views registered by rc-engine (SQL, created in `context.rs`):
- `latest_reserve(mint, reserve_amount, as_of_ts, attestor)`: row with the max `as_of_ts` per mint.
- `supply(mint, supply)`: `supply_after` of the last event by `(slot, tx_index)` across mints ∪ burns.

## 3. Rules (rules/*.sql)

Every rule returns rows with at least `mint` (plus `signature`, `slot` where an event exists).

```sql
-- R1 unbacked_mint
SELECT m.mint, m.signature, m.slot, m.supply_after, r.reserve_amount, r.as_of_ts, r.attestor
FROM mints m JOIN latest_reserve r ON m.mint = r.mint
WHERE m.supply_after > r.reserve_amount
ORDER BY m.slot, m.tx_index;

-- R2 non_allowlisted_holder
SELECT b.mint, b.owner, b.amount, b.slot
FROM balances b LEFT JOIN allowlist a ON b.mint = a.mint AND b.owner = a.owner
WHERE b.amount > 0 AND a.owner IS NULL
ORDER BY b.mint, b.owner;

-- R3 holder_concentration (> 20%)
SELECT b.mint, b.owner, b.amount, s.supply
FROM balances b JOIN supply s ON b.mint = s.mint
WHERE s.supply > 0
  AND CAST(b.amount AS DECIMAL(38,0)) * 10000 > CAST(s.supply AS DECIMAL(38,0)) * 2000
ORDER BY b.mint, b.owner;

-- R4 privileged_change
SELECT mint, signature, slot, change_kind, old_value, new_value
FROM authority_changes
WHERE change_kind IN ('mint_authority','freeze_authority','permanent_delegate','transfer_hook_program')
ORDER BY slot, tx_index;
```

R1 compares against the latest attested reserve, not the reserve that applied at mint time. This is a known v0 limitation and gets stated in the README.

### rc-ingest
```rust
#[async_trait] pub trait RpcSource {
    async fn signatures(&self, address: &str, before: Option<&str>) -> Result<Vec<SigInfo>, IngestError>; // ≤1000, finalized
    async fn transaction(&self, sig: &str) -> Result<Option<Value>, IngestError>;   // jsonParsed, maxSupportedTransactionVersion 0
    async fn token_supply(&self, mint: &str) -> Result<u64, IngestError>;
    async fn token_accounts_by_mint(&self, mint: &str) -> Result<(u64 /*slot*/, Vec<Balance>), IngestError>; // getProgramAccounts, Token-2022, memcmp mint
    async fn mint_info(&self, mint: &str) -> Result<MintInfo, IngestError>;  // authorities, permanent delegate, hook program
}
pub struct HttpRpc { url: String, client: reqwest::Client }             // impl RpcSource
pub struct Ingester<R: RpcSource> { rpc: R, mint: String, seen: HashSet<String>, newest: Option<String>, events: ParsedEvents }
impl<R: RpcSource> Ingester<R> {
    pub async fn poll(&mut self) -> Result<PollReport, IngestError>;   // pages until newest seen; dedups
    pub fn register(&self) -> Register;                                // events + balances snapshot
}
pub fn parse_transaction(tx: &Value, mint: &str, pdelegate: Option<&str>) -> Result<Vec<Event>, IngestError>; // outer + inner ixs; meta.err != null → empty
pub fn compute_supply(events: &mut [Event]) -> Result<(), IngestError>; // checked add/sub; sorted by (slot, tx_index)
pub fn verify_reserve(r: &Reserve, attestors: &[String], now_ts: i64) -> Result<(), ReserveError>;
pub fn reserve_message(r: &Reserve) -> Vec<u8>;   // canonical JSON of all fields except sig
```
Parsed instruction types (names verified against Agave v4.3.0 `transaction-status/src/parse_token.rs`): `mintTo`, `mintToChecked`, `burn`, `burnChecked`, `transfer`, `transferChecked`, `transferCheckedWithFee`, `setAuthority`, `updateTransferHook`, `initializePermanentDelegate`, and **`batch`**. A `batch` holds inner token instructions in `info.instructions`; the parser recurses into them, so a `mintTo` wrapped in a batch is not a bypass.

- Match instructions by **`programId == TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb`**, not by the `program` label. The jsonParsed label is shared with legacy SPL Token.
- `setAuthority`: count it only when `info.account == mint`. Map `authorityType` like this: `mintTokens`→mint_authority, `freezeAccount`→freeze_authority, `permanentDelegate`→permanent_delegate, `transferHookProgramId`→transfer_hook_program, `closeMint`→close_authority, anything else (`pause`, `metadataPointer`, …)→other.
- Walk outer and inner instructions (`meta.innerInstructions`), so CPI mints are caught. `tx_index` is the transaction's position in the block, from `getBlock`. If that's unavailable, use the reverse order of the signature page within a slot (documented).
- Any instruction on the Token-2022 program touching our mint that isn't in the list above gets counted in `PollReport.unparsed` and logged. The parser never drops it silently.

## 5. How each piece is verified

| Area | Test (all offline, RecordBatch or saved JSON; no live RPC in `cargo test`) |
|---|---|
| rc-types | JSON → Register → batches round trip; row counts per table; schema field names/types match §2; `u64::MAX` survives |
| R1 | pass: supply 1,000 vs reserve 1,000 → 0 rows. fail: mint to 1,100 → exactly 1 row (sig, slot, 1100, 1000). Edge: no reserve for mint → 0 rows (documented; flagged separately as stale/missing reserve) |
| R2 | pass: 3 allowlisted holders. fail: 1 non-allowlisted holder with balance>0 → that row; zero-balance stranger → not reported |
| R3 | pass: 3 holders ≤20%. fail: holder at 20%+1 base unit → reported; exactly 20% → not. Overflow: amounts near `u64::MAX` don't error or wrap |
| R4 | pass: only `close_authority`/`other` → 0 rows. fail: hook swap A→B then B→A in two txs → 2 rows in slot order (red-team g) |
| rc-engine | rule loading sorted and hashed; bad SQL file → `EngineError::Rule{file}`; empty tables → 0 violations, no panic |
| rc-ingest parse | one test per fixture in fixtures/rpc: mintTo, mintToChecked, burnChecked via permanent delegate (via_permanent_delegate=true), transferChecked, setAuthority→ChangeKind, updateTransferHook, CPI inner mintTo picked up, `batch`-wrapped mintTo picked up, legacy SPL Token program ix with same shape ignored, failed tx → no events |
| rc-ingest poll | fake RpcSource: >1000 sigs across 3 pages all fetched (red-team h); duplicate sig across pages processed once; out-of-order slots sorted; supply drift vs `token_supply` → `R0_supply_drift` |
| reserves | valid sig accepted; flipped byte rejected; unknown attestor rejected; future `as_of_ts` rejected |
| rc-proof | golden file: fixed violation → exact canonical JSON + hash; key order shuffle → same hash; `commitment` is always `finalized` |
| rc-attest | LiteSVM: init_config; register_rule; post_result OK; non-authority post → error; duplicate result_hash → error; account sizes |
| E2E (manual, devnet) | `scripts/demo.sh mint 100` → R1 proof file within 60s; `rc attest` tx visible in explorer |

## 6. Out of scope (v0)

Yellowstone/Geyser streaming · mainnet · confidential transfers and the confidential mint/burn extension (per-holder rules impossible and confidential supply isn't visible; stated in README; devnet mint is created without it) · multisig authority · Chainlink/Brevis reserve inputs · intra-month issuance budget · reserve-at-mint-time matching · auth on the dashboard · webhook retries.

## 7. Build order (matches poc_plan)

1. Workspace + rc-types + fixtures + rules + rc-engine tests (green offline)
2. rc-ingest with saved RPC fixtures
3. devnet_setup.sh → real mint, capture fixtures
4. rc-proof + rc-cli watch → live R1 on devnet

Cut order if late: dashboard → R3 → on-chain attest (keep hash in JSON) → webhook.
